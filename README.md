# ant-examples

Small, runnable projects that show how the [ant](https://github.com/skudra-go/ant) ORM is used in practice.

ant is a Go ORM. Models are plain structs, queries are checked by the compiler, and there is no code generation step. Columns are referenced through field pointers such as `&U.Age` instead of strings, changes are saved through `SaveChanges`, and schema changes are generated from your structs as plain SQL files that you own. It runs on PostgreSQL, and these examples do too.

```go
adults, err := db.Users.
    Where(ant.Gt(&U.Age, 18)). // ant.Gt(&U.Age, "18") does not compile
    Include(&U.Posts).         // batched, no N+1
    All(ctx)
```

## Examples

| Example | Shows |
| --- | --- |
| [blog](examples/blog/) | A JSON API started from nothing: models, relations, migrations from the first table to a rename, data migrations, a view, seeding, and deployment with Docker |
| [audit](examples/audit/) | An audit service: tables partitioned by month, events with their affected persons stored apart, retention on a cron schedule that drops old months, and search and reporting across it all |
| [ledger](examples/ledger/) | Double-entry bookkeeping for several tenants: transfers that are safe to retry, balances the database enforces, an outbox for reliable events, encrypted fields, and concurrency tests |

Each example is a Go module with its own migrations and a `docker-compose.yml`, so one command runs it:

```sh
cd examples/blog
docker compose up --build
```

They use ports 8080, 8081, and 8082, so you can run them side by side.

## Which situation are you in?

**A new project.** Read the [blog](examples/blog/). Its README explains the folder layout and why it is laid out that way, and its migration history was generated by the real commands, one model change at a time.

**A service that keeps a lot of data for a limited time.** Read the [audit](examples/audit/) example, which shows partitions, composite keys, and retention.

**Money, or anything else that must never be wrong.** Read the [ledger](examples/ledger/) example, which shows what belongs in the database, what belongs in Go, and how to test the difference.

**A project with a running database and its own migrations.** ant does not generate structs from a database, because the mapping is ambiguous and a person or an AI assistant does it better. It gives you a way to check the work instead: dump your schema, write the models, and let `drift` list what still differs until nothing does. Then `adopt` and `baseline` start the history without touching your data. The [guide](https://github.com/skudra-go/ant/blob/main/docs/migrations.md#adopting-an-existing-database) walks through it, and includes a prompt to give your assistant. An example of this is planned.

**Keeping another migration tool.** ant's commands that write SQL need no database, and the files are plain SQL in a common layout, so you can use `diff` and `check` and leave running them to the tool you have.

## Building against a local ant

ant is not published yet, so the examples' `go.mod` files point at a checkout next to this repository:

```text
skudra-go/
├── ant/
└── ant-examples/
```

Once ant is tagged, the `replace` line goes, and each example builds on its own.

You need Go 1.27 or later to work on an example outside Docker. To change one, `make fmt` lays out the code, and `make lint` checks it. Both need [golangci-lint](https://golangci-lint.run) v2.
