# ant-examples

Small, runnable projects that show how the [ant](https://github.com/skudra-go/ant) ORM is used in practice.

ant is a Go ORM. Models are plain structs, queries are checked by the compiler, and there is no code generation step. Columns are referenced through field pointers such as `&Users.Age` instead of strings, changes are saved through `SaveChanges`, and schema changes are generated from your structs as plain SQL files that you own. hello runs on SQLite with nothing to install. The others run on PostgreSQL in Docker.

```go
adults, err := db.Users.
    Where(ant.Gt(&Users.Age, 18)). // ant.Gt(&Users.Age, "18") does not compile
    Include(&Users.Posts).         // batched, no N+1
    All(ctx)
```

## Examples

| Example | Shows | Needs |
| --- | --- | --- |
| [hello](examples/hello/) | ant in one file on SQLite: models, a relation, a typed query, `SaveChanges` | Go 1.27 |
| [blog](examples/blog/) | A JSON API started from nothing: models, relations, migrations from the first table to a rename, data migrations, a view, seeding, and deployment with Docker | Docker |
| [audit](examples/audit/) | An audit service: tables partitioned by month, events with their affected persons stored apart, retention on a cron schedule that drops old months, and search and reporting across it all | Docker |
| [ledger](examples/ledger/) | Double-entry bookkeeping for several tenants: transfers that are safe to retry, balances the database enforces, an outbox for reliable events, encrypted fields, and concurrency tests | Docker |

## Run one

**hello** needs only Go:

```sh
git clone https://github.com/skudra-go/ant-examples
cd ant-examples/examples/hello
go run .
```

```text
Created Alice
Alice is 30 and has 2 posts
Happy birthday, Alice
```

The first run takes about 30 seconds, mostly compiling the SQLite driver. Data goes to `hello.db`; delete it to start over.

**blog, audit and ledger** build against an ant checkout next to this repository, so clone both:

```sh
mkdir skudra-go && cd skudra-go
git clone https://github.com/skudra-go/ant
git clone https://github.com/skudra-go/ant-examples
cd ant-examples/examples/blog   # or audit, or ledger
docker compose up --build
```

This starts PostgreSQL, runs the migrations, loads demo data and serves the API on port 8080 (blog), 8081 (audit) or 8082 (ledger). Each example's README lists requests to try.

## Which situation are you in?

**Trying ant for the first time.** Run [hello](examples/hello/), then change it.

**A new project.** Read the [blog](examples/blog/). Its README explains the folder layout and why it is laid out that way, and its migration history was generated by the real commands, one model change at a time.

**A service that keeps a lot of data for a limited time.** Read the [audit](examples/audit/) example, which shows partitions, composite keys, and retention.

**Money, or anything else that must never be wrong.** Read the [ledger](examples/ledger/) example, which shows what belongs in the database, what belongs in Go, and how to test the difference.

**A project with a running database and its own migrations.** ant does not generate structs from a database, because the mapping is ambiguous and a person or an AI assistant does it better. It gives you a way to check the work instead: dump your schema, write the models, and let `drift` list what still differs until nothing does. Then `adopt` and `baseline` start the history without touching your data. The [guide](https://skudra.net/migrations/adopting) walks through it, and includes a prompt to give your assistant. An example of this is planned.

**Keeping another migration tool.** ant's commands that write SQL need no database, and the files are plain SQL in a common layout, so you can use `diff` and `check` and leave running them to the tool you have.

## Building against a local ant

blog, audit and ledger use the ant checkout next to this repository, which also lets you try them against unreleased changes:

```text
skudra-go/
├── ant/
└── ant-examples/
```

You need Go 1.27 or later to work on an example outside Docker. To change one, `make fmt` lays out the code, and `make lint` checks it. Both need [golangci-lint](https://golangci-lint.run) v2.
